A look inside what I built on my own

In daily use

Sharelog Holmes, the AI support orchestrator

Sharelog is the front door of the support desk. Device alerts, Slack messages and tickets from Atlas, the support operations center I built (more below), all reach it. It answers what it can and hands every other job to a specialist agent: investigating a device, comparing two versions, finding the change behind a bug, drafting the Jira ticket, writing the daily report.

Code checks rights, budget and approval before any agent starts. Agents pass their work to each other as reports, briefs and drafts, and progress and results go back to the Slack thread.

Incident handling went from more than an hour of manual work to about 10 minutes from alert to R&D escalation.

In use

Atlas, a support operations center (SOC)

The place support runs from: the ticket system, the Release Manager, the daily reports, and the Agents Console, which tracks what every agent does and spends over time.

Devices that detect a fault open their own tickets. An AI support engineer reviews each one, routes it to the right agents, and starts an investigation or a remote recovery when needed. When the case is fixed or escalated to R&D, it closes the ticket and adds the lesson to the knowledge base.

Tickets resolved within SLA rose to about 98%.

Twice daily

Fleet health report

Twice a day an agent reads telemetry and the alert channels, decides the status of every device, and sends every department one short report, with a next step for each device that needs attention.

Every release

Version Gateway

An agent that follows a component version through the whole delivery. At each gate it compares the new version with the current one, keeps only the differences that are statistically real, names the risks and recommends go or no-go. After the release it keeps watching, so a slow regression still gets caught.

Used by 6 departments

Release Manager

The tool that controls releases, part of Atlas. Every version moves through the same approved stages and can be stopped or rolled back at any point. Everyone sees what runs where, and every change is logged.

Six departments now request, track and monitor releases here instead of in scattered Slack announcements.

On escalation

Change Investigator

When a bug is escalated to R&D, this agent helps pinpoint where it comes from. It lines up telemetry with version rollouts and configuration changes and narrows the cause down to one change.

Internal service

Retailer Launchpad

Onboarding a new retail chain used to mean copying a long checklist. Now it is a web app with phases, owners and sign-offs, and an LLM-based check engine that verifies on its own every step it can.

Running

Production monitoring

Monitoring for the production fleet. Its alerts go to the ticket system, to Slack and straight to the support agent, so a fault starts its own investigation.

Also: a personal assistant that keeps my own work documented.

How support works today

One support desk, two hubs

Faulty devices open tickets in Atlas, the support operations center. Questions and new versions go to Sharelog, the AI orchestrator in Slack, which hands each job to the right agent. The AI does the checking, the writing and the recovery. People approve what goes to engineering and make the go or no-go call on releases. Click any box to see what it does.

Cheap checks first, one job at a time

Most messages never reach a model. Plain code filters who is asking, a small model decides whether a message is meant for Sharelog, and only then does the main model write a reply and pick one job. Code, not the model, checks rights, budget and approval before any agent starts.

    How I build these
    
      
    
      
    
        
    I start from the job a person on the team does by hand and the point where it hurts. Then I build the smallest agent that does that one job, test it on real cases, and only then give it to the team.
    
        
    Agents read first. Every command on a device goes through one gate with an allowlist and an audit log. Nothing reaches the engineers or a customer without a named person saying yes. Every job has a spending limit, and secrets are masked before anything is posted.
    
        
    I also teach colleagues to use AI and agents in their own work. I like taking an idea, breaking it into tasks, planning it and building it.
    
        
    I work in Claude Code with Python, Docker, Slack, Mixpanel, Elastic, Jira and whatever the team already uses.
